Google 연동 계획

개인 브리더가 자신의 Google 계정으로 사진·서류·기록을 여러 기기에서 관리하는 방식

1. 결정한 방향

별도 서버를 먼저 운영하지 않고, 사용자가 본인의 Google 계정으로 로그인해 Drive에 파일을, Sheets에 관리 기록을, Calendar에 필요한 일정만 저장한다.

이 방식은 집 PC와 휴대전화에서 같은 자료를 볼 수 있게 하며, 개인용 첫 버전에서 서버 운영비와 관리 부담을 줄인다.

2. 데이터가 저장되는 곳

저장 대상Google 서비스예시
개체·서류·수량·증식 기록Google Sheets개체 이름, 종, 서류 ID, 처음·남은 수량, 양도·폐사 기록
개체 사진·서류 PDF·이미지Google Drive개체 대표 사진, 산란·부화 사진, CITES 관련 서류 파일
확인이 필요한 일정Google Calendar부화 예정일, 기록 확인일, 사용자가 직접 추가한 알림

3. 사용 흐름

  1. 사용자가 Google 계정 연결을 누르고 본인 계정으로 로그인한다.
  2. 처음 연결할 때 사진·파일 저장, 기록표 관리, 캘린더 일정 추가 권한을 필요한 범위에서만 허용한다.
  3. 사진·서류 파일은 개인 Drive의 전용 폴더에 저장한다.
  4. 개체·서류·수량 변화 기록은 개인 Sheets에 저장하고, 화면은 이 기록을 다시 불러온다.
  5. 사용자가 원할 때만 부화 예정일 같은 일정을 Calendar에 추가한다.

4. 안전 원칙

  • Google 비밀번호, 개인 파일, 로그인 토큰을 프로젝트 파일이나 GitHub에 저장하지 않는다.
  • Google 로그인은 사용자가 직접 허용하는 방식으로만 진행한다.
  • 파일 권한은 가능한 한 이 앱이 만든 파일 범위로 제한한다.
  • 서류 수량이 0이 되어도 파일을 자동 삭제하지 않는다. 삭제는 사용자가 확인한 뒤에만 한다.
  • Calendar는 내부 알림을 보완하는 선택 기능으로 두며, 사용자가 원하지 않으면 연결하지 않는다.

5. 구현 순서

  1. Google Cloud 프로젝트와 웹용 로그인 설정을 만든다.
  2. Google 계정 연결·해제 화면을 추가한다.
  3. Sheets에 개체·서류·수량 기록을 저장하고 불러온다.
  4. Drive에 사진·서류 파일을 저장하고, 기록에 파일 주소를 연결한다.
  5. 선택한 일정만 Calendar에 추가한다.
  6. PC와 휴대전화에서 같은 계정으로 기록이 보이는지 확인한다.

6. 실제 연결 전에 필요한 사용자 준비

  1. Google 계정으로 Google Cloud Console에 로그인한다.
  2. 새 프로젝트를 만들고 Drive API, Google Sheets API를 켠다. Calendar는 나중에 필요할 때 켠다.
  3. OAuth 동의 화면을 설정하고, 웹 애플리케이션용 OAuth 클라이언트 ID를 만든다.
  4. 허용된 웹 주소에 GitHub Pages 주소 https://kjhchhy.github.io를 등록한다.
  5. 생성된 클라이언트 ID만 알려 준다. 클라이언트 비밀번호나 Google 비밀번호는 절대 보내지 않는다.

7. 이번 단계에서 아직 하지 않는 일

여러 직원의 권한 관리, 자동 파일 삭제, 자동 사진 압축, 상시 서버 운영은 개인용 Google 연동이 안정적으로 동작한 뒤에 검토한다.
